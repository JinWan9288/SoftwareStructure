### ADR-006：付费课程资源采用“时间戳防盗链与短期动态 Token 鉴权”机制

---

> **状态:** Accepted
> **日期:** 2026-06-03
> **关联场景:**  QAS-005 (核心点播资源防盗刷) 
> **关联模块:** 鉴权网关, 媒体服务
>
> ---

#### 1. 背景 (Context)
平台核心商业模式依赖高价值付费课程的购买、点播回看与直播进入（QAS-004）。如果系统对音视频资源的拉流 URL（如点播的 `.mp4`/`.m3u8` 地址或直播的 `.flv` 地址）采用静态、固定的文件路径暴露，恶意用户或盗版爬虫只需通过简单的浏览器 F12 抓包，即可将视频源地址长久截获，并分享到外部网站进行非法盗播和刷课。这将严重破坏公司的核心资产和知识产权，需要通过低性能损耗、高安全性的鉴权手段解决。

#### 2. 决策 (Decision)
在媒体资源的获取路径上，实施基于对称密钥的客户端动态 Token 签名与时间戳防盗链鉴权机制：
* **权限预检**：当学生在前端点击观看时，请求首先到达系统的 `API Gateway`，网关路由至权益服务检查该用户是否真实购买了该课程、且当前账号未在多端重复登录。
* **动态签名生成**：校验通过后，媒体服务利用与 CDN 边缘节点共享的对称私钥，将 `User_ID`、`Course_ID`、客户端 `Client_IP` 以及当前服务器时间戳（`Timestamp`）组合，计算生成一个高强度的 MD5 签名加密串（`SignToken`）。
* **下发短期有效 URL**：拼接后的拉流地址格式增加 `auth_key=timestamp-rand-uid-signtoken` 伪参数。该 URL 设置严苛的 5 分钟绝对过期时间（TTL）。
* **边缘节点 O(1) 级验证**：客户端播放器向 CDN 边缘节点发起连接时，边缘节点在网络层直接提取 `auth_key` 进行原地哈希运算，并校验时间戳是否过期、IP 是否一致。校验通过则直接吐出视频流，失败则直接拦截并返回 HTTP 403。

#### 3. 备选方案 (Alternatives)
* **方案A：标准 HTTP Cookie / Session 集中回源鉴权**
    * *缺点*：流媒体传输和标准的 HTTP 网页请求生命周期不同。长连接（FLV）或高频切片（HLS）如果每次都返回源站进行核心 Session 校验，会导致源站鉴权网关在万人并发下瞬间遭遇性能瓶颈，且第三方 CDN 无法直接读取和解密主站的 Session 数据库。
* **方案B：全链路数字版权管理（DRM 硬件级加密，如 Widevine / FairPlay）**
    * *缺点*：安全性最高（防录屏、防物理抓包），但是技术栈极度繁重，需要支付昂贵的商业授权许可，播放器 SDK 的多端兼容性开发难度极大。对于期末大作业原型项目而言属于严重过度设计。

#### 4. 后果 (Consequences)
* **收益（高性能与防盗播）**：由于 URL 强制绑定了当前学生的 IP，盗用者即使截获了 URL 并转发出去，其他 IP 的用户在 CDN 边缘验证时也会因 IP 不匹配被直接秒杀。CDN 边缘节点执行 MD5 签名校验是纯内存、O(1) 复杂度的计算，无需回源查库，完美契合万人高并发拉流的吞吐量要求。
* **代价/权衡（时钟同步债务）**：该架构强依赖平台源站服务器与第三方 CDN 边缘节点的时钟同步。如果两者出现超过 5 分钟的系统时钟漂移，将导致全网合法合规的学生遭遇大面积鉴权失败（403 无法上课），必须在运维侧配置高可靠的 NTP 定时同步任务。

#### 5. 验证计划 (Validation)
* **防盗链篡改与重放测试**：
    1. 模拟合法用户 A（IP: 192.168.1.5）正常购买课程，获取带有 `auth_key` 的拉流 URL，验证其可以顺畅播放。
    2. 复制该拉流 URL，立即在另一台不同网络的测试机 B（IP: 10.0.5.12）上尝试使用播放器拉流。
    3. 保持测试机 A 的环境不变，等待 6 分钟后（使其超过 5 分钟 TTL），再次使用原 URL 建立连接。
* **预期结果**：验证后两种异常测试场景下，CDN 模拟节点是否均能够 100% 拒绝流传输，并向客户端精确返回 `HTTP 403 Forbidden`，证明签名防盗链彻底生效。
