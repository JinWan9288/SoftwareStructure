### ADR-002：进入直播间采用“权益缓存+短期播放令牌+分级限流与熔断”设计

---

> **状态:** Accepted
> **日期:** 2026-05-28
> **关联场景:** QA-P1 (高并发性能), QA-A2 (系统保护)
> **关联模块**: 直播接入服务 
>
> ---

####  **1. 背景（Context）**

开课前 10 分钟，系统将面临高达 20,000 QPS 的进入直播间突发读流量，每次请求都需要校验用户购买权益，并调用第三方视频云 API 获取底层的防盗链推拉流地址。
底层关系型数据库绝对无法承受如此规模的瞬间查询打宽，同时，第三方视频云 API 在高峰期极易发生 2 秒以上的延迟抖动。如果不实施严格的资源隔离与降级策略，外部接口的慢响应会迅速耗尽 Web 应用的线程池，导致平台整体瘫痪以及服务雪崩。

#### 2. 决策驱动因素(Factors)

当学生点击“进入直播间”时，我们需要关注的驱动因素如下：

- **QAS-001**: 核心入口流量洪峰处理突发大流量下系统核心入口平稳抗峰，响应延迟不劣化。
- **QAS-003**: 视频云接口抖动(可用性)视频云鉴权或流分配 API 发生大面积性能退化时，拒绝无限制的线程阻塞等待，主动断开外部连接并触发熔断。
- **约束**: 外部流媒体基础设施的网络质量不可控，业务系统线程资源有限。

#### 3. 备选方案 (Alternatives)
* **方案A: 直连数据库与视频云同步校验（早期已废弃方案）**
    -  **描述**: 每次请求到达，Web 线程串行执行 SQL 查库校验，并同步发起 HTTP 请求调用第三方视频云 API 换取播放地址。
    -  **优点**: 业务开发成本极低，代码逻辑直观，具备绝对的数据强一致性。
    - **缺点**: 数据库在万级 QPS 下瞬时挂起，且外部 API 一旦发生慢响应，会迅速阻塞源站的 Web 线程池。
    -  **对质量属性的影响**: 确保了数据强一致性，但使得系统的性能与可用性几乎为零。 
* **方案B: 多级缓存屏障与防御性熔断限流架构**
    *  **描述**: 拆分独立的直播接入服务。使用本地 L1 (Caffeine) + 分布式 L2 (Redis) 缓存学生权益；对视频云 API 设置 200ms 严苛超时并外包 Sentinel 断路器；超过单机阈值的请求通过网关直接返回 429 降级页面。 
    * **优点**: 缓存彻底卸载了 DB 读压力，断路器实现了外部故障的物理隔离，Fail-fast 机制保障了核心服务的平稳。 
    * **缺点**: 权益状态存在 60 秒内的最终一致性可见性延迟。
    * **对质量属性的影响**: 极大提升了系统的性能（高吞吐量）与可用性（防雪崩），适度妥协了数据的强一致性。


#### 4. 决策结果 (Result)
综上，**目前采用方案B对当前环境更有利。**
在高并发核心入口场景下，“防雪崩与低延迟”具有压倒性的优先级。而方案 B 虽然让退款等极少数边缘业务存在秒级的一致性窗口延迟，但它同样能 100% 免疫 QAS-003 所定义的外部视频云接口抖动带来的灾难性后果，是高可用架构的最佳权衡。

#### 5. 后果 (Consequences)

- **正面影响**：入口稳态响应 P95 控制在 300ms 内，系统在 30s 内可完成异常断路器全开，核心服务器线程池阻塞率不超过 10%。

- **负面影响/权衡**：退款用户的权益移除存在短暂滞后，可能导致秒级的越权看播风险（经业务评估完全可控）。

- **引入的技术债务** ：需要额外维护一套 Redis 集群与本地缓存的同步失效逻辑，并需要精细配置 Sentinel 的熔断窗口与半开探测机制。

#### 6. 验证计划 (Validation)
在压测环境注入视频云 Mock 服务并设置 2s 慢响应，利用 Locust 压至 10,000 QPS，验证断路器是否在 30 秒内全开并触发快速失败。 详细验证过程见：[链接到 docs/05_evidence/PoC_Report.md 第二部分](../05_evidence/PoC_Report.md)
