## 质量属性场景清单

**QAS-001: 进入直播间洪峰 (性能)**
**关联ADR**: ADR-002
优先级: Must Have

| **要素** | **描述**                                                     |
| -------- | ------------------------------------------------------------ |
| 刺激源   | 移动端与 Web 端集中上课的学生                                |
| 刺激     | 进入直播间的请求突增，达到 **20,000 QPS**                    |
| 环境     | 开课前十分钟的高峰并发环境                                   |
| 制品     | 直播入口网关与鉴权服务                                       |
| 响应     | 首先迅速返回直播间元信息与播放鉴权令牌；若触发限流降级，返回“正在排队中”的响应并记录 |
| 响应度量 | 稳态负载下，**查询的P95响应时间控制在300ms内**，且错误率<0.1%；触发降级后的 P95 响应时间应在 200ms内 |

**QAS-002: 课程详情高频浏览 (性能)**
**关联ADR**: 暂无 
**优先级**: Should Have

| **要素** | **描述**                                                     |
| -------- | ------------------------------------------------------------ |
| 刺激源   | 大量浏览课程的用户                                           |
| 刺激     | 课程详情与课程目录的查询达到 **10,000 QPS**                  |
| 环境     | 日常营销推送或活动大促引发的高峰环境                         |
| 制品     | 课程服务层与分布式缓存                                       |
| 响应     | 系统快速返回课程信息，底层数据库不受到冲击                   |
| 响应度量 | **在活动高峰引发的1,0000 QPS 高频浏览负载下，课程查询的P95响应时间不应超过150ms**，五分钟窗口内多级缓存命中率需稳定在 95%以上，且透传至底层数据库的QPS必须严格限制在 1,000 以下，确保数据库连接池不被耗尽 |

**QAS-003: 视频云接口抖动 (可用性)**
**关联ADR**: ADR-002
**优先级**: Must Have

| **要素** | **描述**                                                     |
| :------- | :----------------------------------------------------------- |
| 刺激源   | 外部强依赖的第三方视频云服务集群                             |
| 刺激     | 视频云鉴权或流分配 API 发生大面积性能退化，响应延迟从 200ms 攀升至 2s，且 HTTP 5xx 错误率飙升至 20% |
| 环境     | 系平台处于公网常态化的高并发直播接入状态                     |
| 制品     | 直播接入服务与熔断器                                         |
| 响应     | 系统准确识别外部依赖的异常波动，拒绝无限制的线程阻塞等待，主动断开外部连接并触发熔断；<br />直到外部服务恢复后，通过半开探测机制自动恢复流量 |
| 响应度量 | 异常发生后 **30s内完成断路器全开**，核心应用服务器线程池阻塞率不超过10%；降级期间非依赖视频云的边缘业务全局错误率增幅<1% |

**QAS-004: 支付回调重复与延迟 (可用性/一致性)**
**关联ADR**: ADR-001
**优先级**: Must Have

| **要素** | **描述**                                                     |
| -------- | ------------------------------------------------------------ |
| 刺激源   | 第三方支付平台（如支付宝或微信支付）                         |
| 刺激     | 网络异常导致针对同一 `paymentOrderId` 最多发生 5 次的冗余回调，或延迟 30 分钟回调 |
| 环境     | 平台日常交易核心链路，处理高频发单与回调                     |
| 制品     | 订单处理服务、权益发放服务、分布式消息队列                   |
| 响应     | 系统依据唯一流水号对冗余投递进行快速幂等防重拦截，保障订单状态机单向流转，并通过异步事件驱动完成跨域的权益最终一致性发放 |
| 响应度量 | 针对冗余投递的回调请求，系统幂等拦截的**P95响应延迟应控制在 200ms 以内**，核心课程权益确保最多发放一次，冗余拦截记录须 100% 落入安全审计日志 |

**QAS-005: 点播资源防盗用 (安全性)**
**关联ADR**: 暂无
**优先级**: Must Have

| **要素** | **描述**                                                     |
| -------- | ------------------------------------------------------------ |
| 刺激源   | 未授权的恶意用户或自动化抓包爬虫                             |
| 刺激     | 尝试跨用户重放截获的合法 `PlayToken`，或直接通过伪造的流媒体 URL 批量拉取付费视频切片 |
| 环境     | 平台处于公网常态化暴露的运行环境                             |
| 制品     | 鉴权中心与令牌校验网关                                       |
| 响应     | 系统通过基于时间戳的动态签名机制实施前置校验，识别篡改与过期重放请求，在网络边缘侧直接拒绝非法流量 |
| 响应度量 | 未授权拉流请求直接100% 拦截，拦截后边缘节点直接返回 HTTP 403；<br />合法 Token 的有效生命周期（TTL）**严格限制在 5 分钟内**，且与请求端 IP 或 User-Agent 强绑定 |

**QAS-006: 线上系统故障定位 (可观测性)**
**关联ADR**: 暂无
**优先级**: Should Have

| **要素** | **描述**                                                     |
| -------- | ------------------------------------------------------------ |
| 刺激源   | 生产环境突发性能异常，系统告警                               |
| 刺激     | 系统告警提示“进入直播间”核心 API 的 P95 延迟突增至 1,000ms 以上 |
| 环境     | 高复杂度的分布式微服务集群部署态                             |
| 制品     | 分布式链路追踪系统、日志聚合平台与微服务网关                 |
| 响应     | 系统在各微服务节点与消息中间件之间自动注入并透传全局统一的 `Trace ID`，完整采集并持久化依赖调用耗时、缓存命中等数据，提供贯穿全链路的请求标识 |
| 响应度量 | 从告警触发到拓扑数据可视化的延迟小于10秒，运维人员可通过唯一 `Trace ID` 贯穿全链路日志，在 **5 分钟内**精确定位到具体的慢查询 SQL 或超时的下游 API 节点 |

**QAS-007: 交互功能无缝热更新 (可修改性)**
**关联ADR**: 暂无
**优先级**: Nice to Have

| **要素** | **描述**                                                     |
| -------- | ------------------------------------------------------------ |
| 刺激源   | 业务开发团队                                                 |
| 刺激     | 部署并发布全新版本的**直播间互动答题**业务代码模块           |
| 环境     | 处于生产环境中，多场万人直播正在平稳进行，交易与推拉流链路处于高负载状态 |
| 制品     | 核心业务系统与交互服务微服务模块                             |
| 响应     | 系统利用微服务松耦合架构与负载均衡器的动态权重调整，通过**滚动发布或蓝绿部署**平滑替换旧容器实例，主干业务代码零侵入 |
| 响应度量 | 模块热更新期间，系统需要在 **不停播、不断流** 的前提下完成更新，发布动作对核心交易下单与拉流播放主链路的请求成功率影响为 0%，核心系统代码 0 侵入 |

**QAS-008: 异步学习进度大吞吐量 (性能)**
**关联ADR**: 暂无 
**优先级**: Should Have

| **要素** | **描述**                                                     |
| -------- | ------------------------------------------------------------ |
| 刺激源   | 10,000 名以上数量同时在线观看视频的移动端或电脑端应用        |
| 刺激     | 客户端每 10 秒持续上报一次学习进度，对网关产生高达 **10,000 QPS 的持续性密集写流量** |
| 环境     | 日常高并发在线学习期                                         |
| 制品     | 学习记录服务、消息队列与持久化数据库                         |
| 响应     | 系统采用基于消息队列的**异步削峰架构**接收上报数据并立即响应客户端，后台 Worker 消费组采用**微批处理与窗口聚合计算**，以 `userId + courseId` 为维度在内存中合并进度后，再进行低频的批量持久化落库，从而彻底规避底层 DB 的写锁争用问题 |
| 响应度量 | 进度上报API的**P95响应时间严格控制在100ms以内**，写操作与核心视频拉流主链路实现绝对的异步隔离，学习进度状态的**最终一致性延迟<30 秒** |
