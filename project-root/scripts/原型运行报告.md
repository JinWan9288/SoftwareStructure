## 架构原型验证

#### 1. 验证背景与目标

本测试通过最小可行性架构原型，验证本系统核心架构决策在高并发场景下的有效性。
* **测试场景**：ADR-002a 直播间核心入口大并发读流量验证，模拟开播前“羊群效应”流量洪峰。
* **测试目标**：验证“多级缓存架构”与“限流降级策略”在应对瞬时突发流量时的可用性与性能表现。

如 Locust 压测监控看板所示，系统在遭受 1000 并发模拟的集中流量冲击时，依赖本地代码级构建的多级缓存与幂等拦截策略，成功将 P95 接口响应延迟收敛至稳态的 15ms 以内，且全局错误溢出率为 0%，从代码层面充分验证了架构设计的强容错性。

#### 4. 性能图表分析

从上图的实时监控曲线中，我们可以清晰地观察到架构决策的生效轨迹：

- **绝对的高可用保障（红线始终在底部）**
  如上图监控面板的第一张子图所示，在并发用户数持续爬升、系统吞吐量突破 100+ 的过程中，系统的全局错误率始终保持在 **0%**，红色的 Failures/s 曲线全程死死贴在 0 轴底线，证明了系统在面对洪峰时具备极强的健壮性，彻底消除了旧版同步直连架构中容易出现的级联崩溃问题。

- **典型的缓存击穿耗时 (初始紫线尖峰)** 
  观察第二张子图 `Response Times` 的前半段：由于系统刚启动时缓存为空（冷启动），早期的并发请求穿透了缓存层，触发了底层数据库与第三方视频云的同步回源调用（图中体现为橙色 50th 中位数稳定在 500ms，而紫色的 95th 尾部延迟因排队效应飙升至 2500ms），这真实模拟了无缓存状态下底层服务的性能瓶颈。

- **多级缓存生效的断崖式下跌（后期的紫线黄线下降）**
  在 `22:54:15` 节点附近，随着同一爆款课程的鉴权令牌被成功写入 L1/L2 缓存，后续汹涌而来的请求被缓存层直接拦截并极速返回， 在图表中表现为**尽管底部的并发用户数（蓝线）和总吞吐量（绿线）仍在疯狂上涨，但系统的响应时间（紫线与橙线）却出现了断崖式下跌，瞬间收敛至接近 0ms 的极低水位**。



#### 5. 验证结论

本次原型压测以量化数据证实了 **ADR-002a 架构决策的正确性**。多级缓存机制成功将时间复杂度为 O(N) 的重度外部 I/O 操作降级为 O(1) 的纯内存读取。该架构使得系统能够在不额外增加底层基础设施运算资源的前提下，轻松抵御不断飙升的并发洪峰，完美达成了 QAS 定义的质量属性要求。
